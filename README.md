# Небосвод

Лёгкий погодный сервис-прокси поверх [Open-Meteo](https://open-meteo.com). Один процесс на Python stdlib — без внешних зависимостей, работает в Alpine LXC.

Официальный сайт сервиса: [nebosvod.amofess.ru](https://nebosvod.amofess.ru)

Официальное зеркало: [nebosvod.smkot.ru](https://nebosvod.smkot.ru/)

Своя веб-морда с тёплой темой «Янтарная ночь», кэширование запросов, API для умного дома (Home Assistant / MajorDoMo) и поддержка нескольких городов.

## Возможности

- **Несколько городов** — единый конфиг `config.json`, выбор в веб-интерфейсе.
- **Пакетный запрос** — погода для множества городов одним запросом (`?city_ids=...`), с одним вызовом к Open-Meteo на всю пачку.
- **Кэш с TTL и защитой от «стада»** — параллельные запросы к одному городу не дублируются (single-flight).
- **Кэш на диске** — `cache.json` переживает перезапуск: после рестарта страница отдаёт данные мгновенно, ещё до обращения к Open-Meteo.
- **Прогрев при старте** — сервис сам обновляет все города сразу после запуска (`warmup_on_start`).
- **Фоновое обновление** — кэш тихо освежается каждые N минут (`background_refresh_minutes`), поэтому данные всегда свежие без ожидания.
- **Stale-while-error / stale-while-revalidate** — просроченные данные отдаются сразу, а свежие подтягиваются в фоне; если Open-Meteo недоступен, показываются последние успешные данные с пометкой `stale`.
- **Свой порядок плиток** — зарегистрированные пользователи расставляют города стрелками в настройках; порядок хранится на сервере.
- **Прогноз на ночь** — корректный расчёт окна «закат → рассвет» из почасовых данных (агрегаты: мин/макс температуры, ветер, давление, самый серьёзный код погоды).
- **API для умного дома** — JSON с блоками единиц, стабильными ключами и читаемым UTF-8 (без `\uXXXX`-экранов).
- **Русский язык** — города, описания погоды, румбы ветра, единицы измерения.
- **Без зависимостей** — только `http.server` + `urllib.request`.

## API

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/cities` | Список городов сервиса |
| `GET` | `/api/all-cities` | Список всех городов (синоним `/api/cities`; удобно для автоматизаций) |
| `GET` | `/api/weather?city_id=..` / `?city=alias` | Погода по городу; `&refresh=1` — сбросить кэш |
| `GET` | `/api/weather?city_ids=1,2,3` | **Пакетно:** погода для многих городов одним запросом. Ответ — `{"results": {"<id>": {...}}, "missing": [...]}` |
| `GET` | `/api/geocode?q=..` | Поиск города по имени или координатам |
| `POST` | `/api/cities` | Добавить город `{id}` (резолв координат, 409 если уже есть) |
| `POST` | `/api/settings` | Настройки пользователя: `{display_mode}`, `{city_filter}`, `{city_id, enabled}`, `{city_order: [id, ...]}` |

Ответ дополнен блоками единиц (стандарт Open-Meteo):

```json
"current_units": {"temperature": "°C", "pressure_mmhg": "мм рт. ст.",
                  "wind_speed": "м/с", "wind_direction": "румб", ...}
```

Если внешний источник недоступен, свежие данные заменяются последними успешными и получают поля `stale: true` и `stale_age` (секунд с момента получения).

## Установка

Одна команда на хосте Proxmox (создаёт Alpine LXC, ставит зависимости, клонирует репозиторий и запускает сервис):

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/AmoFess/nebosvod/main/install/nebosvod-standalone.sh)"
```

После установки сервис будет доступен по адресу `http://<ip-контейнера>:8080` (скрипт выведет его в конце).

Опциональные переменные:
- `NEBO_CTID` — желаемый ID контейнера (по умолчанию первый свободный от 200).
- `NEBO_STORAGE` — хранилище rootfs (по умолчанию определяется автоматически).
- `NEBO_GIT_URL` — источник репозитория (по умолчанию GitHub).

## Обновление

Чтобы обновить уже установленный контейнер до последней версии (без переустановки и без потери пользователей и городов):

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/AmoFess/nebosvod/main/install/nebosvod-update.sh)"
```

Скрипт покажет список контейнеров и спросит ID того, который нужно обновить, затем сделает резервную копию базы и конфигурации, подтянет обновления кода и перезапустит сервис. База пользователей и список городов сохраняются. Имя сервиса и каталог установки определяются автоматически.

## Конфигурация

Всё настраивается одним файлом — `config.json`. Он лежит рядом с `server.py`:

| Как установлен сервис | Путь к конфигу | Имя сервиса |
|-----------------------|----------------|-------------|
| Скриптом одной командой | `/opt/nebosvod/config.json` | `nebosvod` |
| Старая ручная установка | `/opt/weather-proxy/config.json` | `weather` |

При установке скриптом файл создаётся сам из `config.json.example` — правьте его сразу, ничего копировать не нужно.

**Как отредактировать (команды на хосте Proxmox):**

```bash
# ID контейнера можно посмотреть так:
pct list

# правим конфиг
pct exec <ID> -- nano /opt/nebosvod/config.json

# после правки — перезапуск сервиса, чтобы изменения применились
pct exec <ID> -- rc-service nebosvod restart
```

### Параметры

| Ключ | По умолчанию | Описание |
|------|--------------|----------|
| `port` | `8080` | Порт веб-интерфейса и API |
| `cache_ttl` | `1200` | Через сколько секунд данные считаются устаревшими и обновляются |
| `warmup_on_start` | `true` | Обновлять все города сразу после запуска сервиса |
| `background_refresh_minutes` | `20` | Как часто освежать кэш в фоне; `0` — выключить фоновое обновление |
| `upstream_timeout` | `10` | Сколько секунд ждать ответа Open-Meteo в одной попытке |
| `upstream_attempts` | `2` | Сколько попыток сделать, прежде чем считать источник недоступным |
| `open_meteo_http` | `false` | Ходить в Open-Meteo по `http://` вместо `https://` — обход блокировки TLS по SNI (см. ниже) |
| `open_meteo_http_batch_chunk` | `1` | Сколько городов в одном запросе к Open-Meteo при `open_meteo_http: true` |
| `locations` | — | Список городов (см. ниже) |

Все ключи, кроме `locations`, необязательны: если их не указывать, применяются значения по умолчанию. Поэтому конфиг со старой установки продолжит работать без правок.

### Поля города в `locations`

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `id` | да | Числовой ID города (Open-Meteo) |
| `name` | да | Название, как оно будет показано |
| `latitude` | да | Широта |
| `longitude` | да | Долгота |
| `alias` | нет | Короткое имя для запросов: `?city=ekb` |
| `timezone` | нет | Часовой пояс, например `Asia/Yekaterinburg` |

### Примеры

**Минимальный — один город:**

```json
{
  "locations": [
    {
      "id": 1486209,
      "name": "Екатеринбург",
      "latitude": 56.85733,
      "longitude": 60.61527
    }
  ]
}
```

**Несколько городов и короткие имена для API:**

```json
{
  "port": 8080,
  "cache_ttl": 1200,
  "locations": [
    {
      "id": 524901,
      "name": "Москва",
      "alias": "moskva",
      "latitude": 55.75204,
      "longitude": 37.61781,
      "timezone": "Europe/Moscow"
    },
    {
      "id": 1486209,
      "name": "Екатеринбург",
      "alias": "ekb",
      "latitude": 56.85733,
      "longitude": 60.61527,
      "timezone": "Asia/Yekaterinburg"
    },
    {
      "id": 556131,
      "name": "Ис",
      "alias": "is",
      "latitude": 58.7909,
      "longitude": 59.7179,
      "timezone": "Asia/Yekaterinburg"
    }
  ]
}
```

Теперь по этим городам можно обращаться и по ID, и по имени: `/api/weather?city=ekb`.

**Максимально свежие данные — обновление каждые 5 минут** (список городов опущен для краткости, он такой же, как выше):

```json
{
  "port": 8080,
  "cache_ttl": 300,
  "warmup_on_start": true,
  "background_refresh_minutes": 5,
  "locations": [ /* ... */ ]
}
```

**Тихий режим — без фоновых обращений к Open-Meteo:**

```json
{
  "port": 8080,
  "cache_ttl": 3600,
  "warmup_on_start": false,
  "background_refresh_minutes": 0,
  "locations": [ /* ... */ ]
}
```

Сервис обращается к внешнему источнику только когда данные действительно запросили (и держит их час). Удобно, если городов много и хочется беречь лимиты Open-Meteo.

### Если Open-Meteo не отвечает (блокировка TLS по SNI)

Некоторые сети (ТСПУ/ДПИ провайдеров) выборочно глушат TLS-рукопожатие
к `api.open-meteo.com` по имени хоста в ClientHello: TCP-порт открывается,
DNS отвечает, но `https`-запрос висит до таймаута. При этом обычный
`http://` на 80-м порту к тому же сервису проходит.

Если у вас такая сеть, добавьте в конфиг:

```json
"open_meteo_http": true
```

Все запросы к Open-Meteo (прогноз и геокодинг) уйдут по `http://` в обход
блокировки. По умолчанию города при этом тянутся по одному
(`open_meteo_http_batch_chunk: 1`): http-фронтенд Open-Meteo не отдаёт
большие пакетные ответы с почасовыми данными. Если ваш источник
справляется с пачками — значение можно поднять.

Вернуть обратно `https` так же просто:

```json
"open_meteo_http": false
```

### Как узнать ID города

```bash
curl "http://<адрес-сервиса>:8080/api/geocode?q=Екатеринбург"
```

В ответе будет `id`, `latitude`, `longitude` — эти значения и вписываются в `locations`. То же самое можно сделать в веб-интерфейсе: поиск города и кнопка добавления.

### Про `cache.json`

Рядом с конфигом сервис создаёт `cache.json` — последние полученные данные, чтобы после перезапуска страница открывалась мгновенно. Этот файл создаётся и обновляется автоматически, править его не нужно, и в репозиторий он не попадает. Удалить его безопасно: сервис наполнит кэш заново при первом запуске.

## Веб-интерфейс

Тема «Янтарная ночь»: слива `#241A38` + янтарь `#E8A33D`, крупный шрифт, mobile-first (1 → 2 → 4 колонки), без glassmorphism — лёгкая даже на слабом железе.
